# pxt-wifi extension

## Notes

- 2026-09-09: New local library `libs/pxt-wifi` added (Grove UART WiFi V2 / ESP32 driver for Calliope mini; ThingSpeak, IFTTT, Adafruit IO, Thingsboard support), also registered in `pxtarget.json` under `bundleddirs`.
- 2026-09-09: pxt locale convention in this repo — English (source) strings are auto-extracted by pxt into `_locales/<pkgname>-strings.json` and `_locales/<pkgname>-jsdoc-strings.json` (not hand-written). Translations live at `_locales/<lang>/<pkgname>-strings.json` (e.g. `libs/core/_locales/de/core-strings.json`) — keyed by **package name**, not by source `.ts` filename.
- 2026-09-09 (CORRECTION to the note above, which originally claimed `pxt.json`'s `files` need not list `_locales/*`): translation files for a bundled lib **MUST** be listed in `pxt.json`'s `files` array. `Package.bundledStringsForFile()` (pxt-core `built/pxt.js` ~line 114648) does `const files = this.config.files; ... if (files.indexOf(fn) > -1) { JSON.parse(this.readFile(fn)) }` — a locale file not in `files` is silently ignored, with no build error. `libs/core` gets away without listing them because the target's core package is localized through a separate `bundled-strings.json` path, so it is NOT a valid model to copy for ordinary libs.
- 2026-09-09: Language-code resolution for extension locale folders — `Util.normalizeLanguageCode()` (pxt-core `built/pxt.js` ~line 98822) returns `["de"]` for a bare code like `de` (single element; no base-lang/lowercase fallbacks), but `["es-ES", "es", "es-es"]` for a regional code. `bundledStringsForFile` tries those in order, so a plain `_locales/es/` folder is found via the second fallback even though the editor's `availableLocales` lists Spanish as `es-ES`.
- 2026-09-09: `MainPackage.localizationStringsAsync()` merges translations only across `this.deps` — the packages of the **currently open project**. An extension's block translations therefore only appear when that extension is actually added to the open project; testing requires a project that depends on pxt-wifi.
- 2026-09-09: After editing a bundled lib's `pxt.json`, `built/target.json` (which embeds each bundled package's config + files under `bundledpkgs`) must be regenerated with `pxt buildtarget` before `pxt serve` reflects the change. Useful check: `node -e "const t=require('./built/target.json'); console.log(Object.keys(t.bundledpkgs['pxt-wifi']))"` and inspecting the embedded `pxt.json`'s `files` array.
- 2026-09-09: Decided to keep `pxt-wifi` in-tree in this monorepo (not extracted to a standalone GitHub-URL extension) for now. If it's ever split out to its own repo, the `"core": "file:../core"` dependency and the `core` entry entirely should be removed from `pxt.json` — GitHub-imported extensions get core injected automatically via the target's `githubCorePackage` config (`calliope-mini/microbit`), not via an explicit dependency.

## Decisions

- 2026-09-09: Fixed build failure `Package not installed: core, did you forget to run 'pxt install'?` in `libs/pxt-wifi`. Root cause: `libs/pxt-wifi/pxt.json` declared `"dependencies": { "core": "*" }`, which tells pxt to resolve "core" as a published/installed package rather than the local sibling folder. Changed to `"core": "file:../core"`, matching the convention used by every other in-repo library (e.g. `libs/motor/pxt.json`). Verified with `pxt build` from `libs/pxt-wifi` — build now proceeds past dependency resolution (exit 0).
- 2026-09-09: Fixed non-working translations in `libs/pxt-wifi`. Root cause: translation files were placed at `_locales/<lang>/main-strings.json` / `main-jsdoc-strings.json` (named after `main.ts`, the source file) and were also explicitly (redundantly) listed in `pxt.json`'s `files`. pxt looks up translations by **package name**, so it never found them under the `main-*` filename. Renamed all four language dirs' files to `_locales/<lang>/pxt-wifi-strings.json` / `pxt-wifi-jsdoc-strings.json`, matching the already-correctly-named auto-generated English source file `_locales/pxt-wifi-strings.json`. Verified with `pxt build`.
- 2026-09-09: Follow-up — in the same change I had also removed the `_locales/*` entries from `pxt.json`'s `files` list, believing them redundant. That was **wrong** and would have kept translations broken on its own (see the correction note above: `bundledStringsForFile` gates on `files.indexOf(fn) > -1`). Restored all eight entries with the corrected `pxt-wifi-*` names, then ran `pxt buildtarget` to regenerate `built/target.json`. Confirmed via `built/target.json` that all 8 locale files are present under `bundledpkgs["pxt-wifi"]` and that the embedded `pxt.json` `files` array lists them. Net fix = correct filenames **and** `files` entries **and** a target rebuild.
